# 破坏实验

**状态：未开始。** 这里会填三条记录，每条都是"关掉一个机制，然后看它怎么坏"。

## 为什么只能这么做

问"没有它会怎样"，读书和多用都答不了——因为在跑着的那个系统里，那个机制一直存在，你观察不到它的缺席。唯一能拿到答案的办法是把它破坏掉，跑一次，记录坏法。

这类记录有个副产品：**它们直接就是面试答案**，而且比任何总结都硬。因为你能说出"我改坏过，它具体是这样坏的"。

## 三个破坏点

| # | 破坏什么 | 预期观察 | 状态 |
|---|---|---|---|
| 1 | **工具错误回灌**——工具失败了，但不把失败信息交回模型 | 它会重复同一个动作、编造结果，还是在同一处反复撞墙 | 未开始 |
| 2 | **按需注入**——把 skill 的说明全量塞进 system prompt，取消按需加载 | 成本和注意力怎么变；有没有出现"读了但用不上"的指令 | 未开始 |
| 3 | **上下文压缩方向**——从开头砍，而不是尾部截断 | 前缀缓存命中率掉多少；成本翻几倍；行为有没有变 | 未开始 |

三个都对应本仓库正在读的那套 harness。改法先手工、可回退，改动点记在这里。

## 记录模板

每条实验一个文件，`experiments/NN-<机制>.md`：

```markdown
# 破坏 N：<机制>

## 改了什么
一句话，附 diff 或文件路径。

## 怎么跑
命令 + 任务输入（一个能复现的小任务，不是"随便聊聊"）。

## 坏法
不是"效果变差了"，是**具体现象**：
- 第几轮开始重复上一个动作
- 报错以什么形式出现在最后
- 有没有出现凭空编造的工具结果

## 代价
如果这是个真实项目，我会付出什么。这一栏逼你说出取舍，不是复述现象。

## 我先前的错误理解
我以为它会……，实际它……
```

## 铁律

- **每一轮都能回退。** 改坏之前先记下原始版本，实验完恢复。
- **一次只改一处。** 同时改两个变量，坏法就分不清是谁造成的。
- **不接真实凭据的仓库。** 破坏实验跑在临时目录或玩具仓库上。
