## 一、角色与层级

| 英文 | 本文译法 | 我读到的意思 | 置信度 |
|---|---|---|---|
| Harness | 宿主 / 运行环境 | 模型之外的一切：循环、工具、上下文、会话、持久化 | 【文档】 |
| Router | 路由器 | 主会话里的那个角色：判断来消息值不值得接单、派给谁；**不做技术拆单** | 【文档】 |
| Orchestrator | 调度者 | 和 Router 基本同指，偏"派活"这一面；中文里偶尔叫"主控" | 【文档】 |
| Engine | 引擎 | 维护规则与状态的那一层，**不是另一个模型**。这条最容易被误读 | 【文档】 |
| Executor | 执行器 | 真正起一个 worker 会话去干活的组件，受并发槽位限制 | 【文档】 |
| Worker | 执行体 | 每个工单一条独立会话、一个独立目录，负责调查、实现、自检、交付 | 【文档】 |

## 二、任务域

| 英文 | 本文译法 | 我读到的意思 | 置信度 |
|---|---|---|---|
| Source | 信源 | 一个把外部载荷（GitHub、飞书）变成事件的插件 | 【文档】 |
| Trigger | 触发 | 信源产出的标准化事件，还没被接受成工作 | 【文档】 |
| Ticket | 工单 | 被接受之后的任务身份。**这是整套设计的中心对象**，不是一次对话 | 【文档】 |
| Mandate | 授权范围 | 这个工单被允许做多大的事。它是结构化数据，不写在提示词里 | 【文档】 |
| Subscription | 订阅 | 哪些后续输入算到这个工单上（比如同一线程里的人类回复） | 【文档】 |
| Assignment | 派工 | 把工单交给哪个执行器、哪个目录、哪个会话 | 【文档】 |
| Slot | 槽位 | 并发名额，够不够决定新工单是排队还是立刻开工 | 【文档】 |
| Report | 内部报告 | worker 自检后的结构化结果。**它是内部产物，不是回给人的消息** | 【文档】 |
| Outbox | 出站箱 | 把结果按原路送回原会话的队列，通用后端模式 | 【文档】 |
| Proactive | 主动 | 三种模式：off / observe（只记录它会做什么）/ auto | 【文档】 |

## 三、和别的框架怎么对

这栏是**概念对照，不是 API 对照**。想拿去做适配的话，别把这里的说法当成对方文档。

| 这里的概念 | 最接近的东西 | 差在哪 |
|---|---|---|
| Router | OpenAI Agents SDK 的 handoff / triage agent | handoff 是把对话转交出去；这里 router 不转交对话，它**派活**，自己继续对外 |
| Ticket | LangGraph 的 thread + checkpoint | thread 是会话的延续单位；ticket 是**任务**的身份，跨会话存在，长于任何一次对话 |
| Mandate | LangGraph 的 interrupt（人工审批）的一部分 | 审批是"这一步能不能做"；mandate 是"这个工单整体的权限边界"，一次定好，贯穿全程 |
| Subscription | 无直接对应 | 它是"后续消息归哪个工单"的路由表，多数框架把这事留给应用层 |
| Worker | 各家的 subagent | 差别在于 worker 有自己的**目录**和**进程槽位**，不只是自己的上下文 |
| Outbox | 通用的 transactional outbox 模式 | 同一套思路，只是投递目标是 IM 线程 |
| Proactive | 无直接对应 | 大多数框架没有"没被叫也想干活、但先只记录"这一档 |

## 四、几个容易混的词

- **Router ≠ Harness。** Router 是 harness 里的一个预设角色，不是同义词。
- **Engine ≠ 模型。** 原文那句"Engine 不是另一个模型"值得抄下来。
- **Report ≠ 回复。** 报告是给系统看的，回复是给人看的，中间隔着 router 的组织和 outbox 的投递。
- **独立目录 ≠ 安全沙箱。** 上游自己的文档特意写了这条边界。
- **dsh 生态里叫 router 的东西至少四类**：任务路由（本文这套）、推理模式路由（persona 轴）、模型档位路由（贵/便宜模型分派）、subagent 分派。同名不同物，搜的时候要看清在说哪个。
