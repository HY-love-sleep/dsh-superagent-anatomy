SUPERAGENT / 设计速览60 秒 · 请求 → 任务 → 交付

01 / 一句话理解

不是「群里放一个聊天机器人」
而是让请求变成可持续跟进的任务

把接单、执行和回信拆开，任务有归属，过程有记录，结果回到原会话。

你提出请求飞书 / GitHub
→
系统组织任务判断、建单、分派
→
Worker 执行调查、制作、验证
→
原会话收结果交付物 / 必要问题
核心对象是 Ticket（工单），不是一条临时的模型对话。

02 / 三种职责

模型判断语义，程序维护状态

Orchestrator 管接单与对外沟通；Worker 管具体工作；Engine 管可编码的规则。

ORCHESTRATOR / 调度者

这是什么任务？交给谁？

接受新工作、关联已有工单、忽略或停止；组织对外回复。

ENGINE / 状态与规则

这一步是否允许？

去重与准入、工单状态、订阅、持久队列与回复条件。

WORKER / 执行者

怎么把任务做对？

读取原请求、调查与实现、自检；报告结果或必要的阻塞。

分工不等于三套模型：Engine 是程序逻辑，不是另一个 Agent。

03 / 新请求怎么进来

先判断能否接，再决定接不接

Source 把外部消息变成 Trigger（事件），保留原文、发送者、线程与回信地址。

消息 → Trigger统一事件格式
→
去重 / 范围避免重复或越界
→
Gate 准入授权与主动规则
→
调度者决定新接 / 关联 / 忽略 / 停止
@ 机器人 ≠ 立即启动 Worker。
消息也可能只是上下文，不是一项新工作。

04 / 接单之后

一项工单，一段可继续的执行上下文

接受后保存任务与授权来源，再异步排队启动；不是在接单瞬间直接执行全部工作。

Ticket + 授权保存原始请求与范围
→
Assignment本次执行安排
→
Executor 准备目录 + 独立 Session
→
Worker 工作读取、执行、自检、报告

目录怎么准备？

由部署的 prepare 命令决定，不内置固定 clone / worktree 流程。

独立上下文 ≠ 安全沙箱

每工单目录与 Session，不代表容器或操作系统权限隔离。

05 / 中途追加要求

继续同一件事，通常不重新接单

在工单自身线程里的相关人类后续消息，通常作为 Input 送回原 Worker。

01

你在原线程补充要求
例如：「把说明再压缩一点。」

02

订阅关系找到原工单
后续消息进入已有 Session。

03

Worker 判断是否仍在范围内
属于原任务就继续；超范围则交回评估。

04

有新线索可继续跟进
人工明确停止的任务不能擅自恢复。

机器人 / CI 可提供上下文；新工作仍需规则授权，不能凭消息恢复已结束任务。

06 / 形成闭环

工作报告不是群消息，就绪也不等于已送达

常规结果回传：先记录事实，再组织回复，最后通过 Outbox 投递到原会话。

Worker report进展 / 就绪 / 必要问题
→
工单记录保存结果与证据
→
调度者 reply按回复条件组织消息
→
Outbox → 原会话持久排队、去重、重试
普通进展留内部；交付结果或确需人处理时再通知。
例外：PR 合并 / 关闭的终态通知，可由系统直接发送。

记住：接单有边界，执行有归属，交付回原处。
